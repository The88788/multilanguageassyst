# Подключение к теме дизайна

## Общая подготовка данных

Плагин использует события Shop-Script для подготовки данных до формирования HTML.
Общий метод `shopMultilanguageassystPlugin::prepareStorefront()` переводит доступные
товар, категорию, страницу, характеристики товара и артикулов, дочерние категории,
списки страниц и хлебные крошки. Он не меняет исходные записи магазина.

У страницы магазина событие `frontend_nav` вызывается до загрузки страницы.
У отдельных тем данные могут запрашиваться внутри самого шаблона. Поэтому для
адаптации предусмотрен вызов при каждом выполнении шаблона:

```smarty
{$ml_context = $wa->shop->multilanguageassystContext()}
{if is_array($ml_context)}
    {foreach $ml_context as $ml_key=>$ml_value}
        {assign var=$ml_key value=$ml_value}
    {/foreach}
{/if}
```

Добавьте блок в начало шаблона, который выводит данные: например `page.html`,
а также перед хлебными крошками в `main.html`. Метод возвращает подготовленные
данные, а `assign` обновляет локальные переменные самого шаблона. Это необходимо:
изменения глобальных переменных через старый `multilanguageassystBootstrap()` могут
не попасть в локальные переменные уже выполняющегося шаблона Smarty.
Блок ничего не печатает. При отключённом плагине штатный механизм
`view_helper_call` возвращает пустой результат. Использование кеша компиляции
Smarty не отменяет выполнение вызова.

Не переносите вызов только в общую шапку Site: содержимое приложения может быть
сформировано раньше. Переключатель порядка вывода не требуется.

## Списки, полученные самим шаблоном

Если шаблон запрашивает список после общей подготовки, переведите результат сразу
после запроса. Сохраните существующие аргументы запроса вашей темы.

```smarty
{$categories = $wa->shop->categories(0, null, true)}
{if class_exists('shopMultilanguageassystPlugin') && shopMultilanguageassystPlugin::enabled()}
    {$categories = shopMultilanguageassystPlugin::categories($categories)}
{/if}

{$shop_pages = $wa->shop->pages()}
{if class_exists('shopMultilanguageassystPlugin') && shopMultilanguageassystPlugin::enabled()}
    {$shop_pages = shopMultilanguageassystPlugin::pages($shop_pages)}
{/if}
```

Проверка класса и активности нужна для безопасного отключения плагина.
`pages()` предназначен для страниц Shop-Script, не для страниц приложений Site,
Blog и других приложений: их ID принадлежат другим таблицам.

## Переключатель

Разместите навигацию в удобном месте темы. Список языков берётся из
`shopMultilanguageassystLanguages::all()`, текущий язык - из
`shopMultilanguageassystPlugin::language()`, ссылка - из
`shopMultilanguageassystPlugin::languageUrl($code)`. Экранируйте подписи и ссылки.
Используйте класс `multilanguageassyst-theme-language`, чтобы автоматический переключатель плагина
не дублировал навигацию темы. При одном языке переключатель можно скрыть.

## Проверка адаптации

Проверьте главную, поиск, карточку товара, категорию и вложенную категорию,
страницу магазина и вложенную страницу, навигацию, хлебные крошки, характеристики
и значения артикулов. Переключите язык обратно на оригинал. Повторите открытие без
очистки кеша. Проверьте отключение плагина и отсутствие дополнительных языков.
Корзина, оформление заказа, сторонние плагины и собственные настройки темы
требуют отдельной проверки; подготовка данных не означает автоматический перевод
всех строк стороннего JavaScript и виджетов.

Для стандартной темы вызов контекста также добавляется в `order.html`,
`checkout.success.html`, `my.order.html`, `my.orders.html`, `my.nav.html` и
`my.profile.html` приложения Site. Области публичного интерфейса личного кабинета
помечаются `data-multilanguageassyst-ui`; имена покупателя, адреса и комментарии - `data-multilanguageassyst-personal`,
чтобы JavaScript не переводил пользовательские данные. Подписи относительных дат
можно пометить `data-multilanguageassyst-date`. JS поддерживает стандартную динамическую форму
`#wa-order-form-wrapper`, её модальные окна и обновление HTML.

Настраиваемые названия доставки/оплаты и сообщения подтверждения доступны в
«Публикации → Фразы интерфейса», а также в экспорте этого типа содержимого.
Штатные названия стран и регионов из справочников Webasyst тоже входят в этот
каталог. Их коды и значения полей адреса не меняются. Названия, для которых нет
перевода, остаются исходными. Произвольные города, возвращаемые внешним плагином
доставки, могут потребовать отдельного подключения к его справочнику.

Названия товаров в личном кабинете переводятся только для показа, по ID товара,
если сохранённое название совпадает с текущим исходным названием товара.
Историческое или вручную изменённое название сохраняется. Суммы, количество,
номера заказов, контакты и сохранённые записи заказов не изменяются.

Если плагин появился в админке, но его обработчики витрины не работают, очистите
кеш штатной командой Webasyst в «Инсталлер → Настройки». При ручной установке
может сохраниться кеш обработчиков событий, созданный до подключения плагина.

Правки темы поставляются отдельно от основного архива плагина. Не заменяйте целые
шаблоны из другой версии темы: переносите необходимые подключения в свою копию.
Совместимость с произвольной темой требует проверки. Файлы Shop-Script и
фреймворка для такой адаптации изменять не требуется.

## Переменные и имена элементов

Параметр языка в адресе витрины: multilanguageassyst_lang. Cookie: shop_multilanguageassyst. Плагин использует DOM-идентификаторы с префиксом multilanguageassyst.

Для динамических подписей отмечайте только блоки интерфейса атрибутом data-multilanguageassyst-ui. Данные покупателя помечайте data-multilanguageassyst-personal. Такие данные не переводятся поиском по тексту страницы.

Казахский перевод блока с {$date} должен сохранять эту переменную. Другой код Smarty в переводе запрещён.
